# Подробный чеклист: модель линейной регрессии от А до Я

**Сквозная аналогия.** Модель — это **ученик-оценщик квартир**. Данные — его учебник. Обучение — это когда он читает учебник и подбирает «правила» (коэффициенты). Тестовая выборка — экзамен по билетам, которых он никогда не видел.

Линейная регрессия ищет формулу вида

```
цена = w₀ + w₁·площадь + w₂·этаж + w₃·расстояние_до_метро + …
```

Подобрать «правильные» веса `w` — это и есть обучение.

**Обозначения:** ✅ обязательно · 🔶 желательно · 💡 по ситуации · ⚠️ внимание · 🚩 красный флаг

- [ ] ✅ **Понять единицу наблюдения.** Одна строка = одна квартира? одна сделка? один день?

  | Метрика | Смысл простыми словами | Когда выбирать |
  |---|---|---|
  | MAE | «В среднем ошибаемся на X рублей» | Нужна понятная бизнесу цифра |

## Этап 6. Подготовка признаков (feature engineering)

> **Аналогия:** переводим учебник на язык, понятный ученику. Линейная модель понимает только числа и только «прямые» зависимости.

### 6.1. Категориальные признаки

- [ ] ✅ **One-Hot Encoding** для категорий без порядка (район, тип дома): каждая категория становится колонкой 0/1.
  - `drop="first"` убирает одну колонку, чтобы избежать «ловушки фиктивных переменных» (полной мультиколлинеарности) у обычной `LinearRegression`.
  - `handle_unknown="ignore"`: если в тесте попадётся новый район, код не упадёт.
- [ ] ✅ **Порядковые категории** («плохое < среднее < хорошее») кодируем числами 0, 1, 2 через `OrdinalEncoder` с явным порядком.
- [ ] 💡 Если категорий очень много (сотни улиц), объединить редкие в `"other"` или использовать target encoding (осторожно, это легко ведёт к утечке).

### 6.2. Числовые признаки

- [ ] ✅ **Масштабирование** через `StandardScaler` (среднее 0, стандартное отклонение 1).
  - Для `LinearRegression` на точность не влияет, но позволяет **сравнивать коэффициенты** между собой.
  - Для Ridge/Lasso и градиентного спуска **обязательно**. Иначе штраф несправедливо бьёт по признакам с маленьким масштабом.
- [ ] 🔶 Логарифмировать скошенные признаки (площадь, доход): `np.log1p(x)`.
- [ ] 💡 Полиномиальные признаки (`x²`, `x³`), если на scatter-графике видна дуга: `PolynomialFeatures(degree=2)`.
  - ⚠️ Число признаков быстро растёт, и вместе с ним риск переобучения. Использовать вместе с регуляризацией.

### 6.3. Новые признаки из головы (domain knowledge)

- [ ] 🔶 Отношения: `жилая / общая площадь`, `этаж / этажность`.
  - ⚠️ `цена_за_м²` как признак — это утечка (в нём уже есть цена)!
- [ ] 🔶 Из дат: год, месяц, день недели, «возраст дома = год продажи − год постройки».
- [ ] 💡 Взаимодействия: `площадь × район_центр`, если в центре метр стоит по-другому.
- [ ] 💡 Флаги: `первый_этаж`, `последний_этаж`.

### 6.4. Собрать всё в Pipeline ✅

*Зачем:* пайплайн гарантирует, что все `fit` (медиана, среднее для scaler, список категорий) считаются **только на train**, а на тесте применяется готовое преобразование. Это автоматическая защита от утечек.

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

num_cols = X_train.select_dtypes(include="number").columns.tolist()
cat_cols = X_train.select_dtypes(exclude="number").columns.tolist()

num_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale",  StandardScaler()),
])
cat_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore", drop="first")),
])
preprocess = ColumnTransformer([
    ("num", num_pipe, num_cols),
    ("cat", cat_pipe, cat_cols),
])
```

### 9.2. Диагноз: переобучение или недообучение?

| Ситуация | Диагноз | Аналогия | Что делать |
|---|---|---|---|

| train плохо, val плохо | Недообучение | Слишком простые «правила» | Новые признаки, трансформации, полиномы |
| train ≈ val, оба хорошо | 🎉 | Понял материал | Переходим к проверке допущений |

## Этап 10. Проверка допущений линейной регрессии (анализ остатков)

> Остаток = `факт − предсказание`. Если модель «поймала» всю закономерность, в остатках должен остаться **только случайный шум**, без всякого узора.

```python

```

- [ ] ✅ **1. Линейность.** График «предсказание → остаток»:
  ```python
  plt.scatter(pred, residuals, alpha=0.3)
  plt.axhline(0, color="r")
  ```
  - Хорошо: бесформенное облако вокруг нуля.
  - 🚩 Дуга (U-образная форма) → зависимость нелинейная. Добавить `x²`, `log`.
- [ ] ✅ **2. Гомоскедастичность** (постоянный разброс ошибок). На том же графике:
  - 🚩 «Воронка» (ошибки растут с ростом предсказания) → чаще всего помогает `log(y)`.
- [ ] 🔶 **3. Нормальность остатков.** Гистограмма и Q-Q plot:
  ```python
  sns.histplot(residuals, kde=True)
  sm.qqplot(residuals, line="s")
  ```
  - Важно в основном для доверительных интервалов и p-values. На точность предсказаний влияет слабо.
- [ ] 🔶 **4. Нет мультиколлинеарности.** VIF (Variance Inflation Factor):
  ```python
  from statsmodels.stats.outliers_influence import variance_inflation_factor

  Xp = X_train_prepared  # уже обработанные признаки (без константы)
  vif = pd.Series(
      [variance_inflation_factor(Xp, i) for i in range(Xp.shape[1])],
      index=names,
  )
  ```
  - VIF > 5–10 → признак почти полностью выражается через другие. Убрать или использовать Ridge.
- [ ] 💡 **5. Независимость ошибок** (важно для временных рядов). Тест Дарбина–Уотсона: значение около 2 = хорошо.
- [ ] 🔶 **6. Влиятельные точки.** Расстояние Кука (`ols.get_influence().cooks_distance`): находит отдельные наблюдения, которые сильно двигают всю модель.

## Этап 11. Улучшение модели

- [ ] ✅ **Регуляризация.** Штраф за слишком большие веса, чтобы модель не «зазубривала»:

## 🚩 Топ-10 частых ошибок (проверьте себя в конце)

1. [ ] Scaler/imputer обучен на всех данных до split → **утечка**.
2. [ ] В признаках есть что-то, вычисленное из `y` → **утечка**.
3. [ ] Временные данные перемешаны случайно → оценка завышена.
4. [ ] Подбирали модель, глядя на test.
5. [ ] Нет бейзлайна → непонятно, хороша ли модель.
6. [ ] Обучали на `log(y)`, а метрики посчитали в логарифмах, забыв `expm1`.
7. [ ] Интерпретировали коэффициенты при сильной мультиколлинеарности.
8. [ ] Сравнивали коэффициенты признаков разного масштаба без стандартизации.

10. [ ] Смотрели только на R², не глядя на остатки.
